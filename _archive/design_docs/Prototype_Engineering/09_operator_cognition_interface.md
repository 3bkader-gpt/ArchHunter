# 09 — Operator Cognition Interface

The physical UI/UX of the prototype is arguably its most critical engineering component. It must act as a cognitive amplifier for the human operator, not a data dump.

## 1. Reducing Cognitive Overload
*   **Progressive Disclosure:** By default, the UI hides extreme detail (like raw HTTP headers or low-confidence nodes). Information is revealed only as the operator drills down into specific sub-graphs.
*   **Noise Filtering:** Automated suppression of "junk" signals that the system determines are highly unlikely to influence an attack hypothesis.

## 2. Hypothesis Prioritization UX
*   **Risk-Ranked Dashboard:** The primary view is not the massive graph, but a sorted list of `AttackHypotheses` generated by the machine.
*   **Actionable Triage:** Operators can instantly click "Validate," "Invalidate," or "Need More Recon" on a hypothesis, which feeds directly back into the Adaptive Feedback System.

## 3. Architectural Focus Modes
*   **Lens Switching:** The operator can toggle "Lenses" over the graph:
    *   *Identity Lens:* Highlights JWT/OAuth/SAML flows.
    *   *Network Lens:* Highlights VPCs, Subnets, and WAFs.
    *   *Parser Lens:* Highlights serialization boundaries (JSON, XML, Protobuf).

## 4. Mechanism-Centric Navigation
*   **Pivot by Mechanism:** Operators can navigate the graph not just by topology, but by vulnerability class. (e.g., "Show me all nodes where a Parser Differential hypothesis is active").
*   **Skill Integration:** The UI links directly back to the `skills/` taxonomy, allowing an operator to click an inferred mechanism and instantly read the human methodology for testing it.
