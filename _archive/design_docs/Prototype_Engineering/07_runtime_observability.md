# 07 — Runtime Observability

For a cognitive runtime to be trusted, its decisions must be fully transparent. The Runtime Observability layer ensures every inference is explainable and debuggable.

## 1. Reasoning Traceability
*   **Inference Traces:** Just like distributed tracing for microservices, the system implements "Inference Tracing." Every `AttackHypothesis` includes a trace ID that links back to the specific agent execution that generated it.
*   **Agent Logs:** High-resolution logs from the Multi-Agent Reasoning Model detail why an agent chose to traverse a specific edge or apply a certain rule.

## 2. Graph Debugging
*   **Graph Linting:** Automated checks run against the in-memory graph to identify orphaned nodes, conflicting edges, or violations of architectural constraints.
*   **State Dump:** Capability to export the exact L1/L2/L3 graph state into a JSON/GraphML format for local debugging in tools like Gephi or Neo4j Bloom.

## 3. Confidence Audit Trails
*   **Score Lineage:** Every `ConfidenceScore` is accompanied by a mathematical audit trail. If a node has a confidence of 0.85, the trail shows `Base (0.5) + Signal A (+0.2) + Operator Boost (+0.15) = 0.85`.
*   **Decay Logs:** Records when and why a specific mechanism's confidence decayed due to lack of reinforcing signals.

## 4. Signal Provenance
*   **Data Lineage:** Every property on a node maps back to the raw JSON string generated by the specific reconnaissance tool (e.g., Katana output line 45).
*   **Tamper-Evident History:** The event-sourced ledger ensures that the history of how a signal mutated the graph cannot be altered without detection.

## 5. Inference Explainability
*   **Human-Readable Rationales:** Agents do not just output numeric risk scores; they output templated, human-readable rationales. (e.g., "Hypothesis generated because Node A uses weak JWT signing AND routes directly to Internal Node B").
