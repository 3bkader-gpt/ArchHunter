# 07 — Human Explainability Validation

To maintain the system's role as a "Cognitive Amplifier," every machine-generated inference must be validated against human-readability and trustworthiness standards.

## 1. Explainability Scoring
Every rationale generated by an agent receives an `ExplainabilityScore`.
*   **Metrics:**
    *   **Simplicity:** Absence of technical jargon in high-level summaries.
    *   **Evidence Density:** Number of `SourceSignalIDs` linked to the rationale.
    *   **Clarity:** Logical flow from "Fact" to "Inference."
*   **Action:** Rationales with scores < 0.5 are flagged for human review or sent back to the agent for "Translation" into a more readable format.

## 2. Provenance Chain Enforcement
*   **Deep Linking:** Every property in the UI must be one-click away from its raw JSON tool output.
*   **Signal Annotations:** Tools like `Katana` and `Httpx` are enhanced with "Provenance IDs" that follow the signal through the normalization and fusion layers.

## 3. Operator Trust Calibration
*   **Shadow Verification:** The system regularly asks operators to blind-verify a sample of machine inferences.
*   **Agreement Tracking:** Calculates a "Trust Calibration Metric" between the operator and specific agents. High disagreement triggers a "Tuning Required" state for that agent.

## 4. Cognitive Overload Prevention
*   **Focus-Aware Rendering:** The UI dims or collapses non-critical nodes based on the operator's current mouse position or focus area.
*   **Hypothesis Summarization:** Instead of listing 100 individual risks, the system groups them into "Thematic Clusters" (e.g., "5 Parser Differentials detected across these 3 edges").

## 5. Auditability Standards
*   **Decision Logs:** Maintains a persistent record of why specific hypotheses were promoted or demoted.
*   **What-Changed Summaries:** When an operator returns to a session, the system provides a natural-language summary of what the machine learned while they were away.
